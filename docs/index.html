Your path to publication

01 / DESCRIBE

Tell us what you built

Complete the publication form with the app's purpose, AI behavior, owners, and risk answers. A maintainer authorizes the target repository and processing.

02 / PREPARE

Work the issues

The toolkit creates one tracking issue and a set of control issues in your solution repository. Each explains why, what to do, evidence to collect, and how Copilot can help.

03 / VALIDATE

Show the evidence

Close required controls as completed, with evidence. Ask a maintainer to comment /validate on the original request. Fix reported gaps.

04 / REVIEW

Get a human decision

A clean automated report earns ready-for-review, not deployment permission. Governance reviews evidence and decides whether to apply approved-for-production.

Risk changes the work, not the accountability

Default risk tiers; organizations can customize the rules
TierTypical signalsWhat changes
LowInternal, public/internal data, small team, read-only integrations, no runtime AI.Core controls across ownership, security, delivery, and operations.
ModerateConfidential data, organization-wide/public audience, business-system writes, or calls to a large language model (LLM) at runtime.Add recovery/capacity exercises; runtime AI adds its own control.
HighExternal exposure, personal (PII), health (PHI), payment-card (PCI), or other regulated data; privileged integrations.Add independent security/privacy review and explicit residual-risk acceptance.

The highest matching tier wins. “AI helped write the code” is different from “the deployed app calls an LLM.” Every tier still requires secure identity, secret handling, and a reviewed deployment path.

A control is a requirement with evidence; a check is an automated signal. Completing issues alone is not readiness: FAIL and UNKNOWN checks block it. See the validation rules.

Use Copilot as a collaborator, not an approver. Ask it to explain your code, propose configuration, and write tests. Never paste credentials or regulated data into a prompt. Review the output and verify live cloud settings with your platform team.

What this toolkit does not promise

A checklist is not a penetration test, compliance certification, or automatic cloud deployment. Repository checks cannot prove your cloud identity, network, logging, or data protections are correct. Keep production environments protected independently of GitHub issue labels.

Administrators: follow the installation walkthrough. Stock support is GitHub.com only. Your governance repository (the hub) creates plans in separate solution repositories; issue generation needs no target toolkit workflow or Azure credentials.
